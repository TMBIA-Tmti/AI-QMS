## Summary

Three correctness fixes targeting audit-question rotation, regulatory data verification wiring, and Phase 5 pipeline-to-Word export.

---

## Fix 1 — Audit Question Rotation: 61 Missing `audit_questions` Fields

**File:** `src/analysis/compliance_rules.py`

**Problem:**  
Clauses 5.4.2 through 8.5.3 (61 out of 71 total clauses) only contained a single `audit_question` string. The `get_audit_question()` function rotates questions by date seed when `audit_questions` has ≥ 2 entries; with only one entry or none, all 61 clauses always returned the same fixed question regardless of date.

**Fix:**  
Added an `audit_questions` list to each of the 61 affected clauses:
- `audit_questions[0]` — exact copy of the existing `audit_question` (backward compatibility)
- `audit_questions[1]` — a second question from a complementary audit angle (process effectiveness, risk escalation, traceability, evidence sufficiency, etc.)

**Result:**  
All 71 ISO 13485:2016 clauses now support date-based question rotation. `grep -c "audit_questions" compliance_rules.py` → 77 (includes 3 utility references + 71 clause entries × 1 each, split across first-10 original and 61 newly added).

---

## Fix 2 — Regulatory Verifier Wiring: `verify_all()` Never Called

**Files:** `src/chainlit_app/app.py`, `src/services/regulatory_verifier.py`

**Problem:**  
`regulatory_verifier.verify_all()` existed but was never imported or called anywhere. All three `export_regulatory_to_word()` call sites in `handle_regulatory_list()` and the download handler passed `verification_report=None`, leaving the Word export's verification section permanently blank.

**Fix:**  
- Added `from src.services.regulatory_verifier import verify_all as _run_regulatory_verify` to `app.py`
- Inserted a Step 0.7 block in `handle_regulatory_list()` that calls `_run_regulatory_verify()` before the baseline Word export; result stored in `_verification_report`
- Passed `verification_report=_verification_report` to:
  - Baseline Word export (Step 1)
  - Final Word export after pipeline completes
  - Download handler `handle_regulatory_export()` Word path (runs a fresh `verify_all()`)

---

## Fix 3 — Phase 5 Verification Report in `PipelineRunResult`

**File:** `src/analysis/pipeline_runner.py`

**Problem:**  
`PipelineRunResult` had no `verification_report` field. Phase 5 (VERIFICATION) cross-examination results — specifically which rows were `flagged_for_ra` — were computed but never surfaced to callers, making it impossible for downstream exports to include Phase 5 findings.

**Fix:**  
- Added `self.verification_report: Optional[dict] = None` to `PipelineRunResult.__init__()`
- After pipeline execution, constructed a `verification_report` dict from `pipeline.state.rows`:
  - `has_data`, `verified_at`, `total_rows`, `flagged_count`, `flagged_items` (clause_id, doc_id, verdict, flagged_for_ra, verification_rounds count)
